# 从 Heptabase 借鉴什么，Folio 如何实现

参考：[Heptabase — Work with AI](https://wiki.heptabase.com/work-with-ai?lang=zh-Hant)（2026-10-28 阅读）。该页面展示白板上下文聊天、附带卡片及资料、将消息拖到白板、来源引用，以及通过 MCP 与外部 AI 配合。

核心启发是把阅读、对话和整理放在同一个工作空间：对话利用当前材料，有价值的回答再成为可组织、可引用的节点。聊天不需要自动替代所有笔记。

| 交互 | Folio 当前实现 |
| --- | --- |
| 围绕白板对话 | 每项目持久聊天；整个画布、选中节点或不附带节点；每轮必带全部项目原始资料，支持全文检索；节点范围不影响资料读取 |
| 回答成为卡片 | 整条消息或部分选区点击/拖入画布，保留消息来源和模型 |
| 多种阅读材料 | 文献原文与同版式中文双窗；飞书播客逐字稿；浏览器采集文章 |
| 资料依据 | PDF 页码、播客时间戳与妙记链接、文章原链接；材料检索与按页读取 |
| 外部 AI | 本机 Codex App Server 持久会话，或 OpenAI 兼容 API；当前不是 Heptabase 的 MCP 集成 |
| 整理成果 | 可编辑节点及无限层级关系，沿用既有飞书同步规则 |

Folio 额外针对当前阅读习惯做了正文及图内英文翻译、飞书妙记转写、飞书文档与画布协作。与 Heptabase 的完整产品相比，本次实现是上述核心流程的第一版，不代表具备其所有资料类型、索引规模或客户端能力。

## 已验证与边界

- 合成浏览器测试：选区/拖入节点、刷新恢复、项目隔离、上下文范围、层级大纲、备份、文章与图片采集、云端两设备更新。
- 真实服务验证：小宇宙单集完成飞书转写，约 4.9 万字符逐字稿；本机 Codex 三轮对话包含服务重启续接；实际生成 52 个层级节点，并通过既有同步进入飞书。
- 原项目通过正常项目切换保留。不同浏览器/站点的数据仓库彼此隔离，不能把另一个浏览器中未打开的项目说成已经迁移。
- 当前 Codex 会话可以在桌面任务列表看到；桌面中额外发送的消息暂不回填工作台。阅读会话只开放资料工具，不等于让网页任意执行本机开发命令。
- 浏览器扩展提供开发者安装包，尚未上架；网站改版和受保护图片可能影响采集。
- 在线服务代码已支持相关入口，但公网部署、云端授权及可用 API 仍需实际配置。本机关闭后不承诺本机任务继续处理。
