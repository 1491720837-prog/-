# 给接手 AI 的说明

先读本文件、README.md、AGENTS.md；部署另读 DEPLOYMENT.md。技能源在 skills/folio-literature/SKILL.md。

## 启动与修改

推荐 Node.js 24。`npm ci`，`npm run check`，`npm test`；`npm run dev` 启动 http://127.0.0.1:4318。macOS 可用 start.command。dist 是实际前端源码，不是可随意删除的构建缓存。后端为 scripts/server.mjs；云端入口 scripts/cloud-server.mjs。浏览器插件在 browser-extension。

本机 Codex 需要在新电脑重新登录；飞书需要安装并授权 lark-cli。API 配置参考 .env.example，在线配置参考 .env.cloud.example；真实凭据不在备份中。全文翻译依赖 macOS 本机工具，具体流程和依赖见技能与 README。

## 数据与恢复

本次备份：[2026-10-30 Release](https://github.com/1491720837-prog/-/releases/tag/backup-2026-10-30)。[本窗口聊天记录](history/CHAT-2026-10-30.md)保存历史需求与回复。备份时：设计判断 9 节点，主动阅读 31 节点，播客 0 节点。

代码仓库不等于个人数据备份。本机项目主要位于浏览器 IndexedDB，通过产品「下载完整备份」导出 .folio.json，再在新设备「导入文献」恢复。不要直接读写浏览器内部数据库。服务端 artifacts 含翻译成果、历史项目导出、飞书同步基线等；GitHub Release 备份附件保存本次可取得的本机资料和聊天。

先阅读 Release 中 BACKUP-README 和 manifest，了解排除项。恢复服务端同步映射前备份现有数据，避免两台机器同时写同一篇飞书文档。保留稳定 projectId、节点 ID、飞书文档 ID 和共同版本；遇到真实内容冲突或评论锚点保护，不得强制覆盖。

## 重要约定

- 英文论文默认全文翻译，包含每张图内文字，合成同页码中文 PDF；保存原项目。
- 每个项目聊天必须可读取原始 PDF / 完整逐字稿 / 文章，画布上下文范围仅控制额外节点。
- 父子关系从左到右，独立分支从上到下。支持图片和来源定位。
- 飞书使用原生编号、来源放引用；图片在所属节点处；评论只有明确写入意图才改正文。
- 修改前核对 README 与测试；UI 测试用隔离数据，不覆盖用户项目。
- 聊天记录是历史需求证据，可能包含已废弃方案；当前代码、明确最新用户要求和实际验收优先。
